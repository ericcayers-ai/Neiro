Conclusion: a MiyEvent-like **onset/offset/pitch/velocity** record keyed by track name is the
repo's real target; **no channel reaches the frontend**, so hands are derived from the track
key (override map > name heuristic `left|lh|hand L` / `right|rh|hand R`), with a documented
channel convention (left=1, right=0) for callers that do have channels. Observed events are
**note-on { timeSec, midi, velocity, channel? }**; the DAW path has no musical timestamp, so
the wired caller samples it at the gate onset (the transport is parked there — see §4).

## 2. New module: `frontend/src/practice/engine.ts`

Public API (pure — no DOM, no window, no audio, no timers, no side effects):

- `parseTarget(tracks, options?)` → `TargetNote { startSec, endSec, midi, velocity, track, hand, index }`, sorted by onset
- `matchEvents(target, observed, options?)` → `{ notes: JudgedNote[{ note, state, deltaMs?, observedIndex? }], extras }` with states `hit | missed | early | late | pending`
  - windows (documented defaults, configurable): `hitWindowMs=150` (exact-tolerance hit), `earlyWindowMs=300`, `lateWindowMs=500`; matchable window never tighter than the hit tolerance
  - chords any order; repeats pair to the earliest unconsumed occurrence; polyphony independent; `hand` filter; `atSec` for live pending/missed boundaries
- `waitGate(target, observed, positionSec, options?)` → `{ outstanding, mayAdvance, requiredPitches }` (generalises `Transport.waitPoints` semantics: every note of the chord, any order; `lookaheadSec=2.0` default; existing gate behaviour untouched)
- `nextExpectedOnset(result, pitch, afterSec)` — next onset the gate waits for (used by the DAW caller)
- `score(result, options?)` → `{ overall, byHand, bySection, practiceThese }`; strict accuracy = hit/total; `practiceThese` ranked worst first (then most-missed)
- `sectionsFromMarkers(target, markers, options?)` — reuses `Marker { time, label }`; falls back to bars from `bpm`/`beatsPerBar`, else a single `All` section

- `frontend/src/practice/geometry.ts` — pure, DOM-free (no canvas, no window, no timers):
  - `timeToX(t, { now, pixelsPerSecond, judgementX })` = `judgementX + (t - now) * pixelsPerSecond`
    (future notes sit to the RIGHT of the judgement line and fall left as `now` advances);
  - `pitchToY(pitch, { low, high, height })` — one lane per semitone, high notes on top; out-of-range
    pitches clamp into the nearest lane;

  - `noteRect(note, layout)` = `{ x, y, w, h, hand, state }` (min width 2 px);

    `showHands` off) and `notePaint(state)`: hue says the hand, fill/outline says the state —
    pending dim fill / hit solid fill / early+late fill + 2px outline / missed hollow outline — so a
    colour-blind user never relies on hue alone.
- `frontend/src/practice/PianoRoll.tsx` — canvas component (props: `JudgedNote[]`, `nowSec`,
